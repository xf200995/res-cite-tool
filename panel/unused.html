资源引用管理 · 工具使用说明
注：本工具在 CocosCreator v2.4.15 环境开发，理论适用 v2.4.x 版本，v2.x 其它版本需验证有效再使用，不适用 v3.x 版本。

一、快速上手

  1. 在“检索范围”选择一种模式：忽略清理目录、指定清理目录或 resources 引用资源查询。
  2. 勾选需要检索的“文件类型”，点击“开始查找”。
  3. 未引用模式下，列表展示未被引用的资源；点击资源行可在资源管理器中定位，点击左侧复选框才是选中/取消选中。
  4. 勾选资源后点击“清理资源”，确认后删除资源文件及其 .meta。
  5. resources 引用资源查询模式下，按“资源引用查找”的格式展示 resources 下被引用的资源及其引用来源。

二、按钮与列表说明

  • 忽略清理目录：检索 assets 下除输入框中列出的目录以外的资源；多个目录用英文或中文逗号分隔，路径相对 assets 目录。
  • 指定清理目录：通过“选择目录”打开文件资源选择器，仅检索所选目录（必须是 assets 内的目录）。
  • resources 引用资源查询：检索 assets/resources 下被其他资源引用的指定类型资源，并按“资源引用查找”的列表格式展示引用来源。
  • 文件类型 / 全部：控制参与检索的资源类型；“全部”可一键全选或取消选中所有类型。
  • 开始查找：按当前检索范围、目录与文件类型执行检索。
  • 全选资源：未全部选中时全选列表，已全选时取消全选；骨骼组按整组选中或取消。
  • 清理资源：清理已勾选的资源；勾选骨骼组时会整组清理。
  • 资源行：点击整行可在资源管理器中定位并选中该资源；勾选/取消需点击左侧复选框。
  • 骨骼组行：显示引擎类型、主资源路径与“骨骼组 · N 个文件”；组头复选框选中整组，点击“查看资源 / 折叠资源”可展开或收起组内关联文件。
  • 引用资源列表（resources 模式）：每个资源的引用列表默认折叠；“N 个引用”右侧的“查看引用 / 折叠引用”可展开该资源的引用来源；列表头右侧的“展开全部引用 / 折叠全部引用”可批量控制。
  • 引用资源行 / 分组标题行：点击可在资源管理器中定位对应资源；点击引用行的“显示”可在系统文件夹中打开该文件。
  • 日志区：日志文本可选中复制；“工具使用说明”打开本说明页面。

三、引用判定与排除规则

  • 数据来源为编辑器导入产物 library/imports 中的序列化引用，覆盖预制体、场景、动画、材质、JSON、图集等对资源 UUID 的引用。
  • 仅统计 assets 下的资源；db://internal 内置资源不参与未引用候选；.meta 文件默认排除。
  • 图片等“主资源 + 子资源”按资源家族聚合；同家族自引用、同一文件内部引用不计为外部引用。
  • 图集排除：png 被同目录同名 .plist 图集引用时，不计为 png 的引用，该 png 不单独列为未引用资源。
  • 骨骼动画排除：png 被同目录同名 Spine（.skel / .atlas）或 DragonBones（.json / .dbbin）引用时，不单独列为未引用资源。
  • 骨骼动画按“资源组”判定：Spine 组 = 主资源 + textures 贴图 + 同名 .atlas；DragonBones 组 = 主资源 + 同名图集 + 图集贴图。组内任一成员被组外资源引用则整组视为已引用；整组都没有外部引用时，按一个骨骼组条目列出，清理时整组删除。
  • 自动图集 .pac：所在目录及所有子目录存在 importer = texture 的资源时，视为该 .pac 仍在使用并保护；目录内完全没有纹理资源时，才可能被列为未引用。
  • 未覆盖：代码中通过路径加载（如 loadRes('resources/xxx')）、require、构建设置（如启动场景）以及间接引用链。

四、什么时候需要“重建索引”

  • 正常不需要：每次查找都会自动检测资源变化并增量刷新，只重读变动资源。
  • 仅建议在这些情况手动重建：怀疑索引异常或结果明显与项目不符；手动改动或删除了缓存文件；从版本控制或其他途径整体替换了资源与 library 目录；切换分支后首次查找结果异常。
  • 索引缓存版本或编辑器版本变化时插件会自动全量重建，无需手动操作。

五、使用事项

  • 检索范围配置、指定目录与文件类型勾选状态会自动保存到 local/res-cite-tool/unused-settings.json，下次启动 Creator 时恢复上次配置。
  • 索引缓存位置：local/res-cite-tool/index-cache.json，删除后下次查找会自动全量重建。
  • resources 目录资源通常由代码动态加载，建议在“忽略清理目录”中加入 resources，避免误判。
  • 清理会删除资源文件及其 .meta，且无法撤销；骨骼组会连同主资源、图集与贴图一起删除。
  • 清理前请确认资源未被代码动态加载或构建设置引用；建议在版本控制下操作，便于恢复。
  • 万级资源项目首次全量构建约 1–3 秒，之后查找为毫秒级。
